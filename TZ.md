Делаем генератор, который превращает любую Anchor-программу Solana в кнопку «сделать из любой сети», и показываем его на спасении позиции Kamino от ликвидации деньгами с Base. Трек Aurora Intents на Encode Solana Hackathon 2026, сдача до **08.11.2026 23:59 UTC-12**.

## Что строим

Connect Anything — веб-приложение и TS-библиотека. Разработчик вставляет program ID Anchor-программы на Solana и выбирает инструкцию. На выходе: форма аргументов, автоматически подставленные аккаунты (PDA, ATA), симуляция на форке mainnet и кнопка «сделать из любой сети». Пользователь с USDC на Base или Arbitrum подписывает одну транзакцию в MetaMask. Aurora Intents Connect привозит деньги на Solana и выполняет инструкцию.

- **Боль:** сейчас каждую интеграцию Connect пишут руками: дискриминатор, порядок аккаунтов, кодирование аргументов, лимиты CU. Так сделаны все примеры в доках Aurora, в SDK поддержки IDL нет.
- **Для кого:** команды Solana-протоколов, которым нужны пользователи из EVM без своего моста; сама Aurora — больше интеграций Connect.
- **Флагманский рецепт: «Спасти позицию Kamino».** Позиция заёмщика близка к ликвидации, а деньги у него на Base. Одна подпись в MetaMask — и долг на Solana погашен. Гасить чужой долг Kamino разрешает: проверено по коду klend.

## Как работает

От program ID до исполненной инструкции — семь шагов. Первые пять делает наш генератор, последние два — SDK Aurora и сам Connect.

1. **IDL.** Грузим on-chain IDL по program ID (аккаунт Anchor IDL) или файл IDL. Формат Anchor 0.30+; старый — конвертируем.
2. **Форма.** По типам IDL строим поля аргументов: числа, pubkey, bool, enum, struct, Option, Vec. Данные инструкции кодирует `BorshCoder` из `@coral-xyz/anchor`.
3. **Аккаунты.** Резолвер заполняет сам:
   - signer → адрес интермедиари пользователя (`ctx.intermediary`);
   - PDA — по seeds из IDL; фиксированные адреса — из IDL;
   - ATA интермедиари — по mint;
   - остальное — поле ввода или подсказка из рецепта (например, reserve из obligation).
4. **Рецепт.** Упорядоченный список инструкций: основная плюс те, что должны идти перед ней. Для klend это `refresh_reserve` и `refresh_obligation`. Сумма берётся из `ctx.amount`.
5. **Симуляция.** Прогоняем рецепт на форке mainnet (Surfpool), заранее положив интермедиари USDC чит-кодом. Отдаём CU, размер транзакции, логи и ошибку понятным текстом. Больше 200k CU или 1232 байт — предупреждение.
6. **Сборка для Connect.** `prepareSolanaSteps` из `@aurora-is-near/intents-connect-wallet/solana`: меняет интермедиари на `{INTERMEDIARY}`, убирает ComputeBudget. Отдаём `SolanaRecipe` как TS-код и как ссылку `/r/<id>`.
7. **Исполнение.** Раннер SDK, flow bridge-in, комиссия `threeRound` (для Solana другой не бывает). До подписи показываем точную сумму и комиссию. После — статусы. При сбое `deriveExecutionRecovery` плюс наши кнопки: повтор (steps-only) или возврат на исходную сеть (`outOperation`).

### Схема

Мы собираем шаги — Aurora везёт деньги и исполняет их на Solana.

```
Connect Anything — наш код
┌──────────────────────┐  ┌──────────────────────┐  ┌──────────────────────┐
│ Генератор            │  │ Симулятор            │  │ Веб                  │
│ IDL → форма →        │  │ форк mainnet         │  │ кнопка и подпись     │
│ аккаунты             │  │ (Surfpool)           │  │ статусы, повтор,     │
│ refresh + инструкция │  │ CU, байты, логи      │  │ возврат              │
└──────────────────────┘  └──────────────────────┘  └──────────────────────┘

Кошелёк на Base ──USDC + шаги рецепта──▶ Прокси ключа ──▶ Intents Connect API
одна подпись в MetaMask                  /api/intents-connect   мост + MPC-подпись
пользователь платит USDC                 добавляет x-api-key    статусы и возвраты
                                                                     │ USDC
                                                                     ▼
Solana:  Интермедиари ──▶ klend ──────────────────────────▶ Позиция в Kamino
         MPC-аккаунт,     refresh_reserve, refresh_obligation  obligation заёмщика
         единств. signer, repay_obligation_liquidity_v2         долг погашен
         получает USDC
```

Наш код — верхний ряд и прокси. Деньги и шаги везёт Intents Connect, на Solana их исполняет интермедиари пользователя; ключ Aurora живёт только в прокси.

## Функции

MVP — то, без чего не сдаём. Стретч берём только после того, как MVP прошёл живой тест на mainnet.

### MVP

- Загрузка IDL по program ID и из файла
- Список инструкций и форма аргументов по типам IDL
- Резолвер аккаунтов: signer, PDA, фиксированные адреса, ATA интермедиари
- Проверка на совместимость с Connect: новый keypair-аккаунт или второй signer → «не поддерживается» с причиной
- Симуляция на форке mainnet: CU, байты, логи
- Рецепт klend с refresh-инструкциями (ручной шаблон)
- Кнопка из EVM-кошелька: Base, Arbitrum, Ethereum
- Статусы исполнения, повтор и возврат при сбое
- Экспорт рецепта: TS-код `SolanaRecipe` и ссылка `/r/<id>`
- Страница «Спасти Kamino»: адрес кошелька → его obligation, LTV, сколько погасить до целевого LTV, кнопка
- Ключ API только на сервере (прокси `/api/intents-connect`)

### Стретч

- Telegram-сторож: следит за LTV и присылает ссылку на спасение
- Сети-источники Solana, NEAR, Stellar (есть в SDK); Tron и TON SDK пока не подписывает
- Автонарезка на несколько исполнений при >200k CU и lookup-таблицы автоматом
- CLI: `npx connect-anything <programId> <instruction>` → файл рецепта
- Swap+repay, когда долг не в USDC (два исполнения: Jupiter, потом repay)

## Рецепт «Спасти позицию Kamino»

Интермедиари гасит чужой долг на Kamino подписью Connect, владелец позиции на Solana ничего не подписывает. Только погашение: добавить залог в чужую позицию klend не даёт (`has_one = owner`).

Инструкции в одной транзакции, по порядку:

1. `refresh_reserve` — по одной на каждый reserve позиции (залоги и долги).
2. `refresh_obligation` — все reserve позиции как remaining accounts.
3. `repay_obligation_liquidity_v2` — сама обновляет farms. В v1 строгий порядок окружающих инструкций, её не берём.

Аккаунты repay:

- `owner` = `{INTERMEDIARY}`. Это только подписант перевода токена, не владелец позиции.
- `obligation` = позиция пользователя (проверяется только `has_one = lending_market`).
- `user_source_liquidity` = USDC ATA интермедиари.
- `liquidity_amount` = `ctx.amount`, точная сумма из `threeRound`. Всё, что сверх долга, остаётся у интермедиари → кнопка «вернуть».

### Лимиты (замеры на реальных repay на mainnet)

| Инструкция                      | CU                   |
| ------------------------------- | -------------------- |
| `refresh_reserve`, каждая       | 14–24k               |
| `refresh_obligation`            | ~31k                 |
| `repay_obligation_liquidity_v2` | ~35k                 |
| Итого: 1 залог + 1 долг         | ~115k (~140k с farm) |

Каждый лишний reserve — ещё 20–25k, так что в 200k влезает позиция с 3–4 reserve. Размер ~20 аккаунтов, ~1000 байт из 1232; запас даст lookup-таблица рынка. Jupiter-своп вместе с repay в 200k не влезает, поэтому в MVP только долги в USDC.

**Сколько гасить.** B — долг в $, C — залог в $, t — целевой LTV. Погашение x: (B − x) / C = t → x = B − t·C. Данные берём из `@kamino-finance/klend-sdk`.

**Тайминг.** От подписи до исполнения на Solana проходит ~150 с, плюс минуты на MPC-подпись. Сторож должен сигналить заранее, а не на пороге ликвидации.

**Демо-позиция.** Тестовый Phantom: залог $10–20 в SOL, займ USDC близко к максимальному LTV. Порог сторожа для демо ставим ниже.

MarginFi не поддерживаем: там чужой долг гасить нельзя, repay требует authority.

## Ограничения Intents Connect

Connect — альфа. Каждое ограничение ниже генератор либо проверяет сам, либо показывает пользователю до подписи.

| Ограничение                                                                                      | Что делаем                                                                                       |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Подписывает только интермедиари, новые keypair-аккаунты нельзя                                   | Инструкции с вторым signer или init на keypair помечаем «не поддерживается». init на PDA — можно |
| ~200k CU и 1232 байта на транзакцию; ≤ 50 шагов, ≤ 16 lookup-таблиц                              | Симуляция и предупреждение; нарезка — стретч                                                     |
| ComputeBudget запрещён, его ставит релейер                                                       | `prepareSolanaSteps` убирает сам                                                                 |
| Для Solana комиссия только `threeRound` (три вызова create)                                      | Точная сумма известна до подписи; на `QUOTE_MOVED` — пересчёт                                    |
| Одно исполнение на кошелёк на сеть (409)                                                         | Вторую кнопку блокируем, даём resume                                                             |
| `OPERATION_FAILED` — терминальный, деньги остаются у интермедиари; откат bridge-in сжигает nonce | Кнопки «Повторить» (steps-only) и «Вернуть» (`outOperation`)                                     |
| Mint должен быть в allow-list релейера Kora                                                      | В списке целей только токены из `GET /api/v1/supported_tokens`                                   |
| Подпись из SDK: EVM, Solana, NEAR, Stellar; Tron и TON — нет                                     | В MVP только EVM                                                                                 |
| Нет testnet                                                                                      | Тесты на mainnet по $1–5, симуляция — на форке                                                   |
| Ключ `x-api-key` нужен на каждый create                                                          | Свой прокси на сервере, в браузер не отдаём                                                      |
| 503 — нет свободного durable nonce                                                               | Повтор через пару секунд                                                                         |
| Solana-направления могут быть выключены для ключа (`solana: null`)                               | Просим Aurora включить в первый же день                                                          |

## Стек и репо

Всё на TypeScript, потому что SDK Aurora и Anchor-клиент — TS. Один репозиторий, pnpm workspaces.

| Папка                   | Что внутри                                                                                     | Ключевые библиотеки                                                                |
| ----------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `packages/core`         | IDL → инструкции → `SolanaRecipe`: загрузка IDL, кодирование, резолвер, проверки совместимости | `@coral-xyz/anchor`, `@solana/web3.js`, `@aurora-is-near/intents-connect-wallet`   |
| `packages/sim`          | Симуляция на форке mainnet, чит-код баланса интермедиари                                       | Surfpool (запасной вариант — LiteSVM)                                              |
| `recipes/kamino-rescue` | Refresh + repay, расчёт LTV и суммы                                                            | `@kamino-finance/klend-sdk`                                                        |
| `apps/web`              | Интерфейс и API-маршруты                                                                       | Next.js, `@aurora-is-near/intents-connect/react`, `intents-connect-wallet/connect` |
| `apps/watch` (стретч)   | Telegram-сторож LTV                                                                            | grammY или чистый Bot API                                                          |

### API (`apps/web`)

- `GET /api/idl/:programId` — IDL и список инструкций
- `POST /api/simulate` — рецепт → CU, байты, логи, вердикт
- `POST /api/recipes` → id; `GET /r/:id` — страница исполнения по ссылке
- `GET /api/kamino/:wallet` — позиции, LTV, сколько гасить
- `/api/intents-connect/*` — прокси к Connect, добавляет `x-api-key`

### Экраны

1. Ввод program ID
2. Выбор инструкции и форма: аргументы, аккаунты с пометкой «найден сам»
3. Отчёт симуляции и экспорт (код, ссылка)
4. Исполнение: кошелёк, сеть и токен источника, комиссия, подпись, статусы, повтор и возврат
5. «Спасти Kamino»: адрес → LTV → сумма → экран 4

Деплой — Vercel или наш VPS. RPC — платный или бесплатный тариф Helius: публичный RPC Solana бьёт 429.
