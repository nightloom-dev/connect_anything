# ТЗ: R (Rust) — симулятор, klend, проверки

Полный контекст проекта — [../TZ.md](../TZ.md). Детальная версия этого ТЗ — [rust.agent.md](rust.agent.md).

## Твоя зона

Всё, что касается рантайма Solana: прогнать рецепт на форке mainnet и честно сказать, пройдёт ли он через Connect.

1. **Сервис симуляции `crates/sim`.** HTTP-сервис на Rust поверх форка Surfpool (запасной вариант — LiteSVM). Перед прогоном кладёт интермедиари USDC, после — отдаёт CU, размер транзакции, логи и ошибку человеческим текстом. Больше 200k CU или 1232 байт — предупреждение.
2. **Рецепт klend.** Разобраться в коде klend: refresh_reserve → refresh_obligation → repay_obligation_liquidity_v2 для чужой позиции. Погасить чужой долг на форке, замерить CU, отдать T точный порядок аккаунтов.
3. **Проверки совместимости** (`packages/core/src/compat.ts`, TS). Второй signer или `init` на keypair → «не поддерживается» с причиной.
4. **Конвертер старого IDL** в формат Anchor 0.30+.
5. **3+ Anchor-программы** (одна — klend) проходят путь IDL → симуляция → рецепт без ручного кода.
6. **Деплой симулятора на VPS.**
7. **Сценарий сбоя для демо:** какой шаг ломаем, чтобы получить `OPERATION_FAILED`, и проверка этого на форке.

Стретч: автонарезка при >200k CU и lookup-таблицы.

## Не твоё

Веб, Connect SDK, подпись в MetaMask, статусы, повтор и возврат, экран Kamino — это T.

## Готово, когда

- Рецепт repay чужой позиции Kamino проходит на форке за ≤ 200k CU и ≤ 1232 байт, цифры видны в ответе.
- Ошибка программы возвращается с именем из IDL, а не только кодом.
- Неподдерживаемая инструкция отклоняется с понятной причиной.
- 3+ программы проходят без ручного кода.
- Симулятор поднимается с нуля по README.
